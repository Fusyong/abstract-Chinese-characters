# Abstract Chinese Characters

把汉字笔画抽象为**有方向的直线、折线与简单曲线**，并在整字 — 部件 — 笔画 — 笔段之间建立可计算的层级。

一个字 → 一组带方向的笔段序列。横撇是两段，横折钩是三段。最复杂的捺是三段（一波三折），楷体长横也是三段；黑体长横可以只有一段。所有的笔段都取自一个有限类型的词表。文档写的是这套上界，具体字体可以少用段、少用动作。

```
        轮廓                       中线                      抽象笔段
   ┌──────────────┐          ┌──────────────┐          ┌──────────────┐
   │   ███████    │          │   ──────┐    │          │   ──────┐    │
   │  ██     ███  │   ──▶    │         │    │   ──▶    │         │    │
   │  ██       ██ │          │         └──  │          │         └──  │
   └──────────────┘          └──────────────┘          └──────────────┘
       字形数据                  笔画骨架                line + line（2 段）
```

## 动机

汉字字形在计算机里通常只有两种形态：

- **轮廓（outline）**：一堆闭合贝塞尔曲线，机器可渲染但不可理解；
- **像素（bitmap）**：可识别但不可计算结构。

而人写字时真正操作的既不是轮廓也不是像素，是一串**带方向的笔画**。把笔画压到"线段 + 简单弧"这个粒度，等于给汉字找到一种既保留结构信息、又足够简单的中间表示——它不关心笔锋细节的每一根曲线，只留下**方向、长度、位置、连接关系、以及起收笔的动作倾向**。

这也正是汉字之所以成为汉字的那个抽象层。

## 核心设计原则

整个项目的取舍都围绕这一条：**用可负担的计算量，尽可能贴近字体的实际情况，但抽象结果必须是有限类型。**

1. **有限类型**  
   抽象结果不是自由几何，而是一个有限的符号词表：笔画类型有限（横、竖、撇……），笔段基元有限（直线、单弧），方向是一个连续角度，身份有 5 个（三段两点）。宽度动作附在笔段上，一段至多两个：平、提、按各为一个，按提、提按各为两个。不另计力度段数。有限性决定了它可以比较、可以统计、可以生成，也决定了模型不会退化成"换一种方式存轮廓"。
2. **能算的不命名**  
   任何形态，只要能由角度、宽度比、转角、曲率这几种基本量算出来，就不再给它起名字。名字只留给参数本身（θ、ρ、r、w）。这条原则的作用是压掉同义词膨胀：书法里形容同一件事可以有十几个词，而坐标轴上只有一个位置。
3. **分辨率可调，词表不变**  
   精度是参数，类型是常量。段数有上界：长横最多三段，捺最多三段（一波三折）。调分辨率改的是坐标、凸度和宽度的精度，不上调这个上界。具体字体可以低于上界。两种精度产出的东西属于同一套词表，可以直接互相比较。
4. **分层，且同一套算子逐层复用**  
   笔段描述形状，笔画描述动作，部件描述结构，整字描述布局。层与层之间只通过明确的接口传递信息，不把上层的语义硬编码进下层。更重要的是：**算子不随层级增加**——笔画之间的关系只有三种，部件之间仍是这三种，不需要为每一层另造一套词汇。层级变多，词汇量不变。
5. **上层由下层算出，不另存**  
   部件是关系图的连通结构，结构类型是相离边的方位，部件关系是跨部件边的折叠——这些都是派生量，一律即时计算。派生量一旦存储，就会与底层的边打架，而且每加一层就要多维护一份一致性。
6. **文档写最复杂的情形，具体字体加以简化**  
   元数据结构按最复杂的字形来定。楷体是这套结构里最复杂的字体：长横分为三段，中段是提按两个宽度动作；捺最多三段，即一波三折。黑体（等线）用同一套结构的简化形式：长横只有一段，宽度动作为平。简化是少用段、少用动作，参数退到默认值（如 θ = 0、ρ = 1）。抽象层不预设哪种字体更"正确"。
7. **保留结构，不保留风格**  
   粗细、墨色、笔锋的细微抖动属于风格，不进抽象。但"这一笔的转角是 −90° 还是 −135°、圆角半径是 0 还是 0.15 em"属于结构，必须保留。

## 抽象层级

```
整字  character            「月」作为独立的字
  ├─ 关系  relation         部件之间：相离 / 相接 / 相交（由下层折叠而来）
  └─ 部件  component        「月」作为「明」「肝」的偏旁
       ├─ 关系  relation    笔画之间：相离 / 相接 / 相交
       ├─ 笔画  stroke      横 / 竖 / 撇 / 横折钩 …
       │    ├─ 笔段  segment    直线 | 单弧，带方向；力度型（一段至多两个宽度动作：平 / 提 / 按 / 按提 / 提按）
       │    └─ 动作  action     入笔 / 行笔 / 收笔 / 转折 / 调锋（挂在笔画的 t 区间上）
       └─ …                 再往下是笔段，笔段之间不再有关系
```

每一层的结构都是同一种形状：**一组节点 + 节点之间的关系**。`关系` 这个词在树里出现两次，不是重复，而是同一个算子在两个尺度上复用——笔画与笔画之间是它，部件与部件之间也是它，判据一字不改。

层级各自解决一个问题：

| 层级 | 回答的问题           | 主要变量                 |
| -- | --------------- | -------------------- |
| 整字 | 这个字怎么排布？        | 部件之间的关系、比例、重心        |
| 部件 | 这一块占多大空间？       | 宽高比、基准线、与相邻部件的间距     |
| 关系 | 这两笔（或这两块）怎么搭上的？ | 相离 / 相交 / 相接 + 少量几何量 |
| 笔画 | 这一笔怎么走？         | 起笔、行笔路径、折角、收笔        |
| 笔段 | 这一段朝哪、多长、直还是弯、多粗？ | 起点、终点、方向、长度、凸度、力度型 |
| 动作 | 这一段在干什么？        | 身份（t 区间）、零长点的几何参数      |

## 已有数据

| 数据         | 内容              | 用途                |
| ---------- | --------------- | ----------------- |
| **字体数据**   | 每个笔画是字形中的独立路径   | 提供几何形状（轮廓）        |
| **部件拆分数据** | 每个字的部件结构（IDS 等） | 提供层级与归属，约束笔画的部件划分 |
| **笔顺数据**   | 阿拉伯数字表示的笔顺      | 提供笔画顺序与类型线索       |

三项数据合起来，已经覆盖了从"墨迹"到"笔段"的全部前置条件——最难的笔画切分不需要自己做。

## 笔段基元：只有两种

要"尽可能描述实际情形"，最直接的做法是引入曲线。但曲线一旦自由，类型就爆了。折中的办法是**只保留一种曲线基元**：

| 基元     | 参数                 | 说明                                            |
| ------ | ------------------ | --------------------------------------------- |
| `line` | 起点、终点              | 直的一段                                          |
| `arc`  | 起点、终点、**凸度 bulge** | 一段单弧（二次贝塞尔 / 圆弧），bulge 是有符号的矢高比：正为向左上凸，负为向右下凸 |

再加一个全局的**宽度**参数（起笔处宽、段末宽），就足以区分"撇的渐细"和"横的等宽"，而参数总量只比直线多一个。宽度怎么随弧长变化，就是下一节说的**力度型**。

`arc` 的凸度连续可调，但它描述的仍然是"一段弧"这一种类型——不会因为字体不同而变成"两段弧"或"S 形"。真正需要 S 形的地方（如"乙"、"心"的卧钩），由两个 `arc` 用相反凸度串起来表达，类型依然封闭。

## 笔画解剖：起笔 · 行笔 · 转折 · 收笔

一个**简单笔画**（横、竖、撇、点……不含转折的）不是一根线，而是一套动作。印刷楷体里至少有三个部分，每个部分只用两个数就能说清：

| 部分     | 数值描述                     | 取值                                        |
| ------ | ------------------------ | ----------------------------------------- |
| **起笔** | 起端方向偏角 θ_in、起端宽度比 ρ_in   | θ_in 是与笔画主方向的夹角；ρ_in = 起端宽度 / 行笔宽度        |
| **行笔** | 由 1—n 个笔段组成              | 直线为主，撇捺带弧；几何决定形状，笔段的力度型决定粗细走向，无需另加参数 |
| **收笔** | 出端方向偏角 θ_out、末端宽度比 ρ_out | ρ_out = 0 即尖收，ρ_out ≈ 1 即平截，ρ_out > 1 即重收 |

起笔、收笔的 θ、ρ 描述两端。宽度动作另外计算，而且一段里最多两个。楷体长横取满三段，中段是提按；黑体长横简化为一段，宽度动作为平。短横（例如横折钩的第一段）也可以只有一段。

```
楷体长横（最复杂：三段；中段为提按）
  起段                 中段：提，然后按                 收段
┌────┬────────────────────────────────────────┬────┐
│    │                                        │    │
└────┴────────────────────────────────────────┴────┘

黑体长横（简化：一段，宽度动作为平）
┌──────────────────────────────────────────────────┐
│                        平                         │
└──────────────────────────────────────────────────┘
```

即便黑体长横只有一段，整笔的 t 上仍可以标入笔、行笔、收笔三个身份。身份和宽度动作是两套标注。

**复合笔画**在折角处还多两个数：有向转角 θ_turn 与折角圆角半径 r。四者的组合只有四种，恰好覆盖汉字里的全部转折：

|                        | r ≈ 0（方折）   | r > 0（圆转）    |
| ---------------------- | ----------- | ------------ |
| **|θ| ≤ 90°**（顺折）      | 横折、竖折、横折钩的肩 | 横折弯、竖弯       |
| **|θ| > 90°**（反折 / 搭锋） | 横撇、撇折、竖提    | 竖弯钩的钩前、竖弯的末端 |

- **方折**：r < 0.02 em，折角处曲率突变，外轮廓不连续
- **圆转**：r ≥ 0.02 em，折角处曲率连续
- **顺折**：|θ| ≤ 90°，后段由前段顺势转出
- **反折**（搭锋）：|θ| > 90°，后段折返，起笔搭压在前段收笔之上，角部有交叠痕

于是复合笔画 = 起笔 + (行笔 + 转折) × n + 收笔。**结构是递归的，词表是封闭的。**

以"横折钩"为例：

```
   起 ρ1.3@50° 行(横)  折 θ=-90° r≈0  行(竖)  折 θ=-120° r>0  收 ρ0@70°
  ┌──┐───────────────┐                                    ╱
  │  └───────────────┘                                    ╱
  └──┘                 │                                 ╱
                       │────────────────────────────────┘
```

段数有上界：横撇 2 段、横折 2 段、横折钩 3 段、竖弯钩 3 段、长横最多 3 段、捺最多 3 段（一波三折）。这是上界，黑体的长横可以只有 1 段。每一段还带着宽度动作，整笔的 t 上还挂着身份，这才是可用的信息量。

### 常见笔画的期望结构

记法：**力度型**列按笔段顺序填写（多段用 `|` 分隔）。一段至多两个宽度动作：平 / 提 / 按各为一个，按提 / 提按各为两个，不另计力度段数。端点列记 `ρ@θ`，ρ 为端点宽度比，θ 为与主方向夹角或转角（负值表示顺时针）。表内段数是上界，具体字体可以更少。表中的「横」指长横；复合笔画里的短横可以只有一段。角度和宽度比是初值。

| 笔画     | 段数  | 基元                | 力度型        | 起笔 ρ@θ   | 收笔 ρ@θ   | 转折 (θ, r)          |
| ------ | --- | ----------------- | ---------- | -------- | -------- | ------------------ |
| 横 一    | 1—3 | line ×1—3         | 楷体长横三段，中段提按；黑体一段、平 | 1.3@50°  | 1.2@0°   | —                  |
| 竖 丨    | 1   | line              | 平          | 1.2@50°  | 1.1@0°   | —                  |
| 撇 丿    | 1   | arc(+)            | 提          | 1.5@50°  | 0@45°    | —                  |
| 捺 ㇏    | 3   | 一波三折（各段直线或单弧，待测量） | 每段至多两个宽度动作 | 1.0@0°   | 0@45°    | —                  |
| 点 丶    | 1   | arc               | 按提         | 1.0@0°   | 0.7@0°   | —                  |
| 提 ㇀    | 1   | line              | 提          | 1.4@50°  | 0@45°    | —                  |
| 横折 乙   | 2   | line + line       | 平 \| 平     | 1.3@50°  | 1.2@0°   | −90°, r≈0          |
| 横撇 乛   | 2   | line + arc        | 平 \| 提     | 1.3@50°  | 0@45°    | −135°, r≈0         |
| 横折钩 ㇆  | 3   | line + line + arc | 平 \| 提 \| 按提 | 1.3@50°  | 0@70°    | −90° r≈0；−120° r>0 |
| 竖弯钩 乚  | 3   | line + arc + arc  | 平 \| 平 \| 按提 | 1.2@50°  | 0@60°    | +90° r>0；+120° r>0 |
| 横折折撇 ㇋ | 3—4 | line ×2 + arc     | 平 \| 平 \| 提  | 1.3@50°  | 0@45°    | −90° r≈0；−135° r≈0 |

这张表既是生成时的模板，也是校验时的上界：楷体长横应为三段，中段为提按；黑体长横应为一段、平。某一段里出现第三个宽度动作，说明这一段里的宽度变化超出了模型，或切段阈值有问题。捺最多三段。若"撇"的收笔 ρ 不为 0，说明端点检测出了问题。表中的角度与宽度比是初值，以测量为准。

调锋不占段，故不列在表中，但它的位置是确定的：带钩的笔画在钩前必有一个（竖末先勒细到 ρ_neck≈0.7，再按出钩），捺在出锋前有一个，横撇在反折处有一个。这三处正好可以当调锋检测的基准点——查不到颈缩，说明宽度剖面算错了。

要注意的是，颈缩只有落在**段与段的边界**上才叫调锋。若它落在某一段内部，就只是这一段的力度型"提按"——形状一样，但没有"换动作"这层含义。两者的分工：**力度型记录形状，调锋记录换笔的位置。**

> 这一节用的是直观说法（起笔、行笔、转折、收笔）。下一节把"动作"形式化，并说明它与笔段的关系为什么不是一一对应；同时补上这里没提的一类：两个动作之间的**调锋**。

## 动作：笔段之上的区间标注

先明确一件事：**动作不是独立于笔段的第三种东西，而是笔段的性质。**

但"性质"不能简单做成每个笔段贴一个标签——黑体长横只有一个笔段，却同时包含起笔、行笔、收笔三个身份。所以身份的载体不是笔段本身，而是**笔画弧长参数 t ∈ [0, 1] 上的一段区间**：

```
黑体长横（t 轴；一个几何段）
0 ────── 0.12 ───────────────────────────── 0.88 ────── 1
│  入笔   │              行笔                │   收笔   │
└──────────── 一个笔段，三个身份 ────────────────┘
  宽度动作：平

楷体长横则是三个几何段，中段的宽度动作是提按（先提后按）。
身份挂在整笔的 t 上，宽度动作挂在段上，一段至多两个。
```

笔段是几何与宽度（在哪、朝哪、多长、多弯、多粗），动作是标注（这一段在干什么）。两者相互独立：一个笔段可以挂多个动作，一个动作也可以跨越多段。

### 两个维度，但挂在不同的东西上

"动作"这个词在日常使用里混着两件事：它在笔画里**扮演什么角色**，和它的**宽度怎么走**。两者的可测条件不同——力度只需一段的轮廓就能量出来，不必知道它属于哪一笔；身份必须站在整笔的高度才能判断，同一段加粗的笔画，在横的开头叫入笔、在钩的根部叫收笔。所以两者不放在同一个载体上：

| 维度     | 回答             | 取值                    | 挂在             |
| ------ | -------------- | --------------------- | -------------- |
| **身份** | 这一段在笔画里扮演什么角色？ | 入笔、行笔、收笔（段）＋ 转折、调锋（点） | 笔画的 t 轴，区间或零长点 |
| **力度** | 这一段的宽度怎么走？     | 平、提、按各一个；按提、提按各两个 | 笔段本身；不另计力度段数 |

这样就不必给每个身份再贴一个力度标签。读的时候各取所需："楷体长横的中段是提按""开头是入笔""黑体长横整段是平"。

宽度变化常常落在身份切换的附近。这条联系只在生成时有用，存储时不必写下来。

身份因此不是五个平行的值，而是**三段时间 + 两个接缝**：入笔、行笔、收笔把笔画分成段，转折与调锋标出段与段之间的接缝（零长，落在区间边界）。

### 命名原则：能算的才留，能算的不取名

这一条决定了整个词表：

1. **每个保留的词都必须对应一个可计算的数值分档，并且写明阈值。** 这些词只是给人读的标签，数据里存的是那个数。
2. **凡是能由已有序参量（角度、宽度比、转角、曲率）算出来的形态，一概不再命名。** 因为命名会引出无限的近义词，而参数只有坐标轴。
3. **只有无法落到任何数值轴上、仅靠视觉印象区分的说法，才整套删掉。**

按此原则，原先的"入笔三型"被删除：斜切、尖起、平起不是三种东西，只是 (θ_in, ρ_in) 平面上的三个区域——给出两个数，类型自然浮现，不需要名字。收笔同理，"出锋 / 顿收 / 平收"就是 ρ_out 的三个区间。

> **不建模清单**：只靠手感区分的（驻、挫、涩行）、纯属比喻的（藏锋、露锋、悬针、垂露、暗过）、以及软笔的锋面操作（换锋、翻笔、绞转）。它们的视觉结果已被 θ、ρ、r、w(s) 覆盖，保留名字只会制造同义词。一波三折已收回，只表示捺最多三段。
>
> **一个例外：调锋。** 它保留，但理由不是"它好看"，而是它不描述形状，而描述**序列上的位置**——"前一个动作在此结束、后一个动作从此开始"。这个位置无法由任何单点测量得出，必须由两侧的动作共同确定；而它又确实留下一个可测的痕迹（宽度颈缩）。所以它按"必须给参数与阈值"的规矩进入身份，见下节。

### 一、身份：三段两点

| 类 | 身份     | 参数                  | 说明                         |
| - | ------ | ------------------- | -------------------------- |
| 段 | **入笔** | θ_in, ρ_in, l_in    | 起端方向偏角、起端宽度比、动作长度（占 t 的比例） |
| 段 | **行笔** | —                   | 形态完全由笔段几何决定，无额外参数          |
| 段 | **收笔** | θ_out, ρ_out, l_out | 出端方向偏角、末端宽度比、动作长度          |
| 点 | **转折** | θ_turn, r           | 有向转角、折角圆角半径（归一化到 em）       |
| 点 | **调锋** | ρ_neck, Δt, δθ      | 颈缩深度、颈缩长度（占笔画长）、经过它的方向偏移   |

段类占 t 区间，点类零长、落在段的边界上。五者都不再细分子类型，需要区分形态时比较参数即可。

### 二、调锋：两个动作之间的接缝

调锋是**一个笔画内部（或两笔之间）两个动作的衔接**：前一个动作收势、笔锋重整、后一个动作起势。在印刷楷体里它留下的可见痕迹是一个**颈缩**——笔画在此处略细，随即恢复。

它和转折最容易混，但两者测的量不同：

| 判据                             | 归为                     |
| ------------------------------ | ---------------------- |
| |θ_turn| ≥ 30°                 | **转折**（方向真的变了）         |
| |θ_turn| < 30° 且 ρ_neck < 0.85 | **调锋**（方向没怎么变，只是勒细了一下） |
| |θ_turn| < 30° 且 ρ_neck ≥ 0.85 | 不记点动作，只是两个段的普通分界       |

其中 ρ_neck = w_min / w̄（局部平均宽），Δt 是颈缩的持续长度，要求 Δt ≤ 0.06（否则不是"接缝"而是一整段变细，应归为力度"提"）。三条阈值把"转折 / 调锋 / 什么都没有"切成三个互不重叠的区域，因此不需要人眼判断。

**三个出现位置，各有归属规则：**

| 位置         | 例                    | 归属                                              |
| ---------- | -------------------- | ----------------------------------------------- |
| 段与段之间（笔画内） | 竖末转钩之前、捺将出锋之前、横撇反折之前 | 记在该笔画的 t 上，落在两段的边界                              |
| 折角之前       | 方折处"先提细再按下"的那个细处     | 记在 t_turn 之前，与转折相邻但不同点                          |
| 笔画与笔画之间    | 前一笔收笔 → 后一笔起笔        | 记在**后一笔的 t = 0**，带 `prev` 指向前一笔；理由是它属于后一笔起笔前的准备 |

**为什么它值得占一个身份，而不是并进"提"**

因为它回答的问题不是"多细"，而是"在哪换动作"。这对三件事有直接用处：

- 生成字体时，起笔/行笔/收笔三套习惯的切换点就在调锋处——没有它，"什么时候换笔"无从表达；
- 笔顺动画的节奏需要停顿与重起，调锋是天然的节拍点；
- 笔画之间的调锋还能标出"这一笔是搭在前一笔上写的"，这是笔顺与结构耦合的地方。

顺带一个对称关系值得记住：**顿是 w 的局部极大，调锋是 w 的局部极小。** 两者是同一条宽度曲线上的两类临界点，地位却不同——顿的形状可以由笔段的力度型"按提"直接读出来，而"接缝在哪"是个位置信息，任何形状都装不下它，所以调锋必须自己占一个身份。

### 三、转折：两个数决定一切

| 参量          | 含义                  | 阈值               |
| ----------- | ------------------- | ---------------- |
| θ_turn      | 后段方向相对前段方向的有向转角     | 正负表示转向侧          |
| r           | 折角的圆角半径             | r < 0.02 em 视为方折 |
| |θ_turn| 下限 | 不足此值不算方向改变，改由调锋判据处理 | 30°              |

|θ_turn| 区分顺折与反折（90° 为界），r 区方折与圆转（0.02 em 为界）。两个数构成一个 2×2 的格子，已经列在上面那张表里。

### 四、力度：笔段的宽度走向

力度是**笔段的属性**。它只用这一段的轮廓就能量出来。这里说的「动作」是**宽度动作**（平、提、按），和挂在 t 上的身份（入笔、行笔、收笔、转折、调锋）不是同一套。一段里最多两个宽度动作。不使用「力度段数」这个计数。

设 w(s) 为笔段沿弧长 s 的宽度。力度型是这一段宽度动作的名字：

| 力度型      | 走向         | 宽度动作 | 附加参数        |
| -------- | ---------- | ---- | ----------- |
| **平**    | \|dw/ds\| < ε，恒定 | 1（平） | —           |
| **提**    | dw/ds < −ε，变细  | 1（提） | —           |
| **按**    | dw/ds > ε，变粗   | 1（按） | —           |
| **按提**   | 先增后减，一个峰   | 2（按，然后提） | 峰位置 t_p、峰宽 w_p |
| **提按**   | 先减后增，一个谷   | 2（提，然后按） | 谷位置 t_v、谷宽 w_v |

ε 可取行笔宽度的 5% 每 em，此值是初值。按提、提按各是两个宽度动作，因为 dw/ds 换了一次号。它们仍是一个力度型，不另计段数。

**为什么一段最多两个。** 一个宽度动作只有三种走向：平、提、按。两个宽度动作里，值得分开的只有次序相反的两种：先按后提（按提，一个峰）、先提后按（提按，一个谷）。「提然后平」这类组合跟单个动作看起来一样，不另立名字。一段里不放第三个宽度动作。更细的宽度变化用更多几何段表达，而段数另有上界：长横最多三段，最复杂的捺也是三段（一波三折的三折）。**按提 ≠ 提按**——峰与谷是两种形状，次序不能交换。

**为什么叫"平"不叫"匀"**：早先用过"匀"，唯一的理由是躲开当时词表里"平截 / 平收"这两个以"平"开头的说法。那两个词已经删了（它们只是 ρ_out 的区间），"平"就空出来了。而"平"比"匀"更贴切：它既指宽度平，也指笔道平直。与身份"行笔"也不再撞字——"行笔的力度是平"读得通。黑体长横就是这一个动作。

**顿与调锋现在都能由力度型读出来**：

- **顿** = 按提的峰（峰宽 w_p 明显大于两侧），或者端点上的加粗（记在 ρ_in / ρ_out 里）。楷体长横的中段可以本身就是提按，这是这一段上的两个宽度动作。
- **调锋** = 提按的谷，但只有在谷恰好落在两个身份的接缝上时才算（见上一节）。落在段内部时，它只是这一段的宽度形状。

这样，"顿"和"调锋"不必各占一个类型，却仍然可查：查一次 dw/ds 的变号点就够了。调锋要不要继续单独占一个身份，见「待测量验证」。

### 为什么这样建模是对的

- **段数与身份各自独立。** 几何段数（长横最多 3、横撇 2、捺最多 3）由折点决定，身份数（起、行、收，再加上转折与调锋）由接缝决定，两者不必相等。宽度动作附在几何段上，一段一个或两个，不另计力度段数。段数超出该笔画的上界，说明折点切多了；某一段里出现第三个宽度动作，说明切段或上界需要重看。
- **类型数最小。** 身份 5 类（三段 + 两点）、力度型 5 种（一个宽度动作三种、两个宽度动作两种），且挂在不同的东西上——不必相乘。原先把力度当身份的属性时，名义上是 15 种组合，其中近一半对不上（"入笔 + 提""调锋 + 按"），还得靠一张合法性表去挡；现在这个问题不存在了。
- **最复杂的结构里，字体可以简化。** 楷体长横三段、中段提按，黑体长横一段、平；楷体 ρ_in≈1.3，黑体 ρ_in≈1.0；楷体折角 r≈0，圆体 r>0.1。同一套 schema，少用段、少用动作即可，不新增字段。
- **可承载生成。** "起笔习惯 / 行笔习惯 / 收笔习惯"三个参数族，就是 θ_in/ρ_in、力度型、θ_out/ρ_out 这三组数。

## 关系：相离 · 相交 · 相接

部件不是一堆笔画的集合，而是**一组笔画加上它们两两之间的关系**。关系只有三种，且都是拓扑概念——只看"两者有没有公共点、公共点在哪"，不涉及审美判断。

这三个词从底下一直用到上面：笔画对笔画用它，部件对部件也用它，判据都不变。

### 三种关系

以中线（骨架）为准判定：

| 关系     | 定义                | 判据                    | 例            |
| ------ | ----------------- | --------------------- | ------------ |
| **相离** | 无公共点              | 中线最近距离 d > δ          | 三的三横、川的三竖、八  |
| **相接** | 有公共点，且交点是一笔或两笔的端点 | 端点落在另一笔中线上（端-端 / 端-身） | 人的撇与捺、山的竖与竖折 |
| **相交** | 有公共点，且交点不在任何一笔的端点 | 两笔中线在各自内部交叉           | 十、七、丈、中      |

δ 取平均笔宽的 0.5 倍：比这更近的两笔，视觉上已经粘连，按相接处理。

三者的区别可以归结为一个量：**公共点离端点多远**。落在端点上（距离≈0）是相接，落在两笔内部是相交，没有公共点是相离。这样判定不依赖人的判断，只依赖骨架的端点集合与距离。

### 每种关系附带少量几何量

关系本身是离散标签，但每种关系还要记几个数，否则部件变换无从计算：

| 关系 | 附带参数                                  |
| -- | ------------------------------------- |
| 相离 | 最距 d、方位（上 / 下 / 左 / 右 / 内 / 外）、是否基准对齐 |
| 相接 | 接触点参数 t（落在哪一笔的哪个位置）、方式（端-端 / 端-身）     |
| 相交 | 交点参数 (t₁, t₂)、交角 θ_cross、出头量          |

2—4 个数，与一个笔段同量级。

### 变换下类型不变，几何量可变

这是关系最有用的性质：**部件变形时，三种关系的类型不变，变的只是几何量。**

以"月"从单字变偏旁为例（宽度压缩约 0.65）：

| 关系      | 压缩前          | 压缩后          | 类型     |
| ------- | ------------ | ------------ | ------ |
| 撇 ↔ 横折钩 | 相离，d≈0.18 em | 相离，d≈0.10 em | **不变** |
| 横 ↔ 竖段  | 相接，t≈0.02    | 相接，t≈0.04    | **不变** |
| 两横之间    | 相离，方位=上下     | 相离，方位=上下     | **不变** |



原因很直接：关系是拓扑量，形状是几何量。几何量在变换下连续变化，拓扑量只在"接触—分离"的临界点才会翻转，而正常的字体变换不会跨过那个临界点。

这条性质也是"部件"能成立的定义依据：**同一个部件在不同字里、不同字体里，几何差得远，关系图几乎不变。** 反过来，如果两笔的关系在变换中翻转（相接变成相交），那说明它们本来就不属于同一个部件。

### 关系图

把所有笔画作为节点、关系作为边，一个部件就得到一张带标签的图：

- **相接 / 相交**把笔画连成"笔画簇"（连通分量）
- **相离**连接不同的簇，并记录方位与间距
- 部件的边界通常与簇的边界一致，但不总是——"三"是一个部件，却是三个互不相连的簇

这张图是后续所有结构操作的骨架：

| 用途    | 怎么用                         |
| ----- | --------------------------- |
| 部件关系  | 跨部件笔画对的折叠（相交 > 相接 > 相离），见下节 |
| 部件判定  | 关系图同构 + 几何量近似 → 判为同一部件      |
| 字形相似度 | 先比关系图（图匹配），几何量只作边权          |
| 拼字    | 拼合时必须保住关系图，否则字形散架           |
| OCR   | 关系图对缩放、位移、笔宽不敏感，是稳定的结构特征    |
| 笔顺教学  | 讲"十是相交、八是相离"，比讲形状清楚得多       |

拼字最能说明问题：把"十"的两笔拉开，关系从相交变成相离，字就变成了"二"；把"人"的撇捺拉开，就变成了"八"。**关系一改，字就换了。**

### 部件之间：同一套关系，往上一层

同一套三个词，不必为部件另造一套。定义很直接——**两个部件的关系，就是它们笔画之间关系的折叠**：

```
R(A, B) =  相交   若 ∃ a∈A, b∈B 使 R(a,b)=相交
           相接   否则若 ∃ a∈A, b∈B 使 R(a,b)=相接
           相离   其余（所有跨部件笔画对都相离）
```

取"最强"的跨对关系作为部件关系：相交 > 相接 > 相离。理由是可见性——只要有一处笔画交叠，两块在视觉上就是一个整体，其余笔画离得多远都不改变这个事实。

| 部件关系   | 例子                                  | 跨部件的笔画对            |
| ------ | ----------------------------------- | ------------------ |
| **相离** | 明（日 ⿰ 月）、炎（火 ⿱ 火）、好（女 ⿰ 子）、树（木 ⿰ 对） | 全部相离               |
| **相接** | 古（十 ⿱ 口）、吉（士 ⿱ 口）、岁（山 ⿱ 夕）          | 十的竖下端落在口的上边框上（端-身） |
| **相交** | 早（日 ⿱ 十）、里（田 ⿱ 土）、重、事、秉             | 十的竖穿入日、里的竖贯穿田土     |

这不需要新增任何测量：笔画之间的关系已经算过一遍，部件关系只是一次 O(|A|·|B|) 的折叠，二三十笔的字不过百余次比较。

### 结构类型不是另一套分类，是相离的方位

这样一来，⿰ ⿱ ⿵ 这些"结构类型"也不用单列了——它们就是**相离关系的方位字段**：

| 结构       | 关系 + 方位    | 附加参数        |
| -------- | ---------- | ----------- |
| 左右 ⿰     | 相离，方位 = 左右 | 宽度比、基线对齐、间距 |
| 上下 ⿱     | 相离，方位 = 上下 | 高度比、中轴对齐、间距 |
| 包围 ⿵ ⿶ ⿷ | 相离，方位 = 内外 | 内部偏置、留白     |
| 交叠 ⿻     | 相接或相交      | 交叠程度（无方位可言） |

IDS 里的 ⿻ 恰好就是这个模型的边界情况：它之所以要单列一个算子，正是因为跨部件边不再是相离。**在这个模型里 ⿻ 不是新算子，是折叠结果落到了另两个取值上。**

### 只有一个部件

有的字在部件数据里只含一个部件。那就是一个部件，不另立「独体字」。相接、相交可以是合法的部件关系（如「古」「早」），不因为跨部件的边接上了，就把这个字改判成另一类。里、重、事、秉、东若在部件数据里是一个部件，就按一个部件处理；数据里分成几块，也先照数据走。

一笔是否同时属于两块、部件数据与关系图不一致时如何记，见「待测量验证」。`relations` 里仍不存部件字段：每笔自己的部件归属来自部件数据，跨部件的边可以筛选出来再折叠。

### 不变性往上提一层

前面那条"变换下类型不变"在部件层先照同一假设使用：**排版变换（左右换上下、压缩、避让、穿插）只改变几何量，不改变部件关系的类型。** 这条假设是否成立，见「待测量验证」。

于是校验变成两级，且都是可断言的：

1. 部件关系图不变（相离的还是相离，相接的还是相接）
2. 每个部件内部，笔画关系图不变

第 1 级管"字有没有散架或粘死"，第 2 级管"部件有没有被压变形"。拼字失败时，先看哪一级报警，就知道是比例分配错了还是逐段变换错了——这比对着字形肉眼找问题快得多。

## 字体相关的简化

同一套元数据，字体越简单，用到的段和动作越少。楷体长横为三段，中段是提按；黑体长横为一段，宽度动作为平。捺的上界是三段（一波三折），哪种字体用满，待测量。其余参数如下，数值均为初值。

| 字体 | θ_in / ρ_in    | 力度型分布         | θ_turn / r 折角  | θ_out / ρ_out    | 调锋 ρ_neck | 可省略的字段               |
| -- | -------------- | ------------- | -------------- | ---------------- | --------- | -------------------- |
| 楷体 | 50°, 1.3       | 长横中段为提按；撇捺带弧 | −90°, r≈0      | 0°, 1.2 / 45°, 0 | 0.7（钩前明显） | 几乎不省                 |
| 宋体 | 30°, 1.1（带装饰角） | 按→提贯穿全段，末端有三角；段数待测量 | −90°, r≈0，折处加粗 | 0°, 2.0          | 0.8       | 装饰角几何可省，只记 ρ_out 偏大  |
| 黑体 | 0°, 1.0        | 长横一段、平        | −90°, r≈0      | 0°, 1.0          | 1.0（无调锋）   | θ 全取 0、ρ 全取 1 时可整段省略 |
| 圆体 | 0°, 1.0        | 全段平           | 任意, r>0.1      | 0°, 1.0          | 0.95      | 折角只记 r，不记 θ 分档       |

简化不是丢信息，而是**让参数退化到默认值**——θ=0、ρ=1、r 取字体常数、ρ_neck=1，这几个默认值本身就说明"这种字体在这个位置没有显著动作"。比较两款字体时，取默认值的参数不参与打分。注意 ρ_neck=1 和 ρ_neck=0.7 是同一套 schema 下的两个数，黑体并不是"没有调锋这个概念"，而是"调锋深度为零"——这两件事在实现上差别很大。

## 计算量预算

抽象的意义之一是让规模可控。以中等笔画复杂度估算：

| 量         | 估计       | 备注                        |
| --------- | -------- | ------------------------- |
| 平均笔画数/字   | ~10      | 常用字 8—12                  |
| 平均笔段数/笔画  | ~2.2     | 长横、捺最多 3；复合笔画 2—4；待测量修正 |
| 平均笔段数/字   | ~22      |                           |
| 参数/笔段     | ~8       | 起终点 4 + 凸度 1 + 宽 2 + 力度型 1（按提、提按另加峰位或谷位、宽度） |
| 关系数/字     | ~10      | 约为笔画数（只记显著关系，不必两两全连）      |
| 参数/关系     | ~3       | 类型 1 + 距/位置 2             |
| 数值/字      | ~210     | 对比轮廓的数千个控制点，压缩 1—2 个数量级   |
| 全字集（2 万字） | ~360 万数值 | 约 30—50 MB，可全量驻留内存        |

部件关系不占新预算：它是跨部件的边的一次折叠，边已经算过，折叠最多百次比较。层级往上加，存储量不涨——**上层的结构是算出来的，不是存出来的**。

这个量级意味着：可以做**全字集的两两比较**（2 万字 × 2 万字不可行，但可以做倒排索引 + 候选筛选），也可以把整个字库塞进一个前端应用里跑。

## 处理流程

```
1. 读字形        fontTools 取出每一笔的封闭轮廓
      │
2. 求中线        Delaunay 三角剖分 → 弦轴（chordal axis）
      │          或 栅格化 → Zhang-Suen 细化 → 骨架追踪
      │
3. 折线化        Ramer–Douglas–Peucker 简化中线
      │
4. 切段          在拐点（内角突变处）断开 → 得到有序线段
      │
5. 定向          按笔顺起点统一每段向量方向
      │
6. 补曲线        对残差大的段升级为 arc，拟合凸度
      │
7. 测参数        首末段取宽度比与方向偏角 → (θ_in, ρ_in) / (θ_out, ρ_out)；折点取转角与圆角半径 → (θ_turn, r)；宽度剖面的局部极小 → (ρ_neck, Δt, δθ)
      │          逐段按 dw/ds 变号次数定力度型：0 次 → 平/提/按（一个宽度动作），1 次 → 按提/提按（两个宽度动作，附峰谷位置与宽度）
      │          一段内不出现第三个宽度动作，不另计力度段数
      │
8. 建关系图      笔画两两求最近距离与交点，按端点性判定相离/相接/相交
      │
9. 归层          用关系图的连通分量 + 部件数据把笔画分组，计算部件包围盒与变换
      │
10. 折叠          取跨部件边，按相交 > 相接 > 相离折叠出部件关系图与结构类型
      │
11. 输出         结构化笔段序列 + 关系图（两级，JSON）
```

第 2 步要处理中线上的短枝和折笔内部的分岔。每一笔若已是独立轮廓，交叉处的粘连不是这一步的问题；细节见「待测量验证」。

第 6 步的触发条件很关键：先按直线拟合，只有当最大偏差超过阈值（例如 0.03 em）时才升级为 arc，避免把所有笔画都强行弯曲。

第 7 步是"可负担"的体现——不去拟合笔锋的精确轮廓，只算几个量：**端点宽度比 ρ**、**端点方向偏角 θ**、**折点转角与圆角半径 (θ_turn, r)**。前两者各是一次局部测量，却足以定位起收笔在 (ρ, θ) 平面中的位置，不需要做任何笔形分类。

调锋也只是同一条宽度曲线上的一个极值点：找到 w(s) 的局部极小，量出深度 ρ_neck、宽度 Δt、以及经过它的方向偏移 δθ。若 ρ_neck ≥ 0.85，这个极小是噪声，丢掉；若 Δt > 0.06，它不是接缝而是一整段变细，归到力度"提"里。**没有"识别调锋"这一步，只有一个极小值检测加两个阈值。**

力度型的判定比调锋更省：沿段扫一遍 w(s)，数 dw/ds 的变号次数——0 次看符号（平 / 提 / 按，一个宽度动作），1 次看先后（按提 / 提按，两个宽度动作）。两个宽度动作的段才多存两个数（峰或谷的位置与宽度）。一段里不放第三个宽度动作，也不另计力度段数。

第 8 步只需在笔画包围盒相交的候选对上计算，平均每字十余次距离查询，代价可忽略。

第 10 步不产生新的测量，只对已有边做一次筛选与折叠，得到部件关系。相接和相交可以是合法的部件关系。部件数据里只有一个部件的字，就按一个部件处理，不另作判定。

字段设计对应五个层级：`box` / `components` 是整字与部件层，`relations` 是关系层（笔画为节点、三种关系为边的图），`geometry` 是笔段层，`strokes` 是笔画层，`actions` 是动作层——动作以 `t` 区间挂在笔画上，零长区间即转折、调锋这类点动作。`press` 写在 `geometry` 上而**不在 `actions` 上**：它是笔段的属性，一段一个；`按提` / `提按` 另带峰（谷）位置与宽度。起收端存 `theta` / `rho`，转折存 `turn` / `r`，调锋存 `rho_neck` / `dt` / `dtheta`；**"方折 / 圆转""顺折 / 反折"这些说法不进数据**，它们只是 (r, |turn|) 两个阈值切出来的区域，需要时现算，不构成一套需要维护的词表。

`relations` 只存关系类型与几何量，不存"部件"这个概念本身——部件是关系图的连通结构，可以随时从图里算出来。

**部件关系也不单独存。** 每条边都连着两笔，而每笔都知道自己属于哪个部件，所以"跨部件边"是一个筛选条件：把 `relations` 里 `strokes[a].component ≠ strokes[b].component` 的那些边取出来，按"相交 > 相接 > 相离"折叠，就得到部件关系图。整字的结构类型（左右 / 上下 / 内外）也由这些边的方位字段给出。层级越往上，越没有独立的字段——上层是下层算出来的，不是另存一份。

## 部件层：变换即理解

同一个"月"，作为单字和作为偏旁，形状并不一样。

```
   月（单字）              月（偏旁，如"明"）
 ┌──────────┐           ┌───────┐
 │          │           │       │
 │   wide   │    ──▶    │ narrow│
 │          │           │       │
 │          │           │       │
 └──────────┘           └───────┘
  宽高比 ~0.85            宽高比 ~0.55
  高度基本不变            高度基本不变
```

如果只做仿射缩放，整个偏旁会横向压扁，竖笔被压细、横笔被压短，字形会散架。真实的字体设计不是这样做的：

| 段类型      | 宽度压缩时         | 高度压缩时     |
| -------- | ------------- | --------- |
| 横（水平段）   | **长度缩短**      | 位置内移，长度不变 |
| 竖（垂直段）   | 位置内移，**长度不变** | 长度缩短      |
| 撇、捺（斜向段） | 角度变陡，长度略减     | 角度变平，长度略减 |
| 折角       | 位置迁移，形状保持     | 同上        |

也就是说，**变换是逐段的、随方向而异的**，而不是一个 2×2 矩阵作用在所有点上。这正是抽象层能提供的东西：因为每一段都知道自己的方向，所以压缩宽度时，可以只把水平分量吸收掉，把垂直分量原样保留。

这套逐段规则执行时有一条硬约束：**变换前后的关系图必须一致**。压缩"月"的宽度后，撇与横折钩仍然是相离、两横仍然与竖相接；一旦某处从相离挤成了相接，说明压缩量超限，字形已经开始糊了。所以变换的停止条件不是"看起来差不多"，而是"关系图不变"——这是可以直接写进代码的判据。

部件划分先照已有的部件数据。关系图用来检查变换有没有把相离、相接、相交挤变。数据里只有一个部件的字，就处理成一个部件。部件数据与关系图不一致、以及一笔穿过两个部件时怎么记，见「待测量验证」。

进一步，部件在整字中的位置也不是自由摆放，而是受结构约束的：

| 位置关系  | 约束                | 例   |
| ----- | ----------------- | --- |
| 左右 ⿰  | 等高，右侧宽度可伸缩，中间留"让" | 明、林 |
| 上下 ⿱  | 等宽，高度按笔画数分配       | 花、曼 |
| 包围 ⿵⿶ | 外框定界，内部居中缩放       | 同、凶 |
| 半包围 ⿵ | 内件偏向右下            | 庆、这 |

这张表里的 ⿰ ⿱ ⿵ 不是另一套枚举，而是相离关系的方位取值（左右 / 上下 / 内外）加上比例与对齐参数。换言之，它回答的不是"属于哪一类结构"，而是"方位定了之后，比例和对齐怎么定"。

"让"（避让）是最能体现结构理解的部分：左偏旁把右下的横向空间腾出来给右部件，这个动作只在抽象层里才看得见——轮廓数据里它只是一堆坐标。

## 应用方向

### 1. 字形相似性比较

先比关系图，再比几何：把两个字的关系图做（带标签的）图同构匹配，得到笔画的一一对应；再在匹配的笔画对之间比较笔段向量距离，以加权和作为相似度。关系图提供"哪些笔该跟哪些笔比"，几何量提供"差多少"。

匹配是两级的，两级用的是同一个三种取值：先匹配**部件关系图**（节点少、几乎不花时间，用来决定"哪块对哪块"），再在配对成功的部件内部匹配**笔画关系图**。这样既避免了大图的组合爆炸，也保证了不会出现"把左边的木配到右边的目"这类荒谬对应。

相比直接比像素或轮廓，这套表示对字体风格、粗细、缩放天然不敏感，只反映结构差异——适合异体字判定、错字检测、古籍异文比对、简繁对应。如果两个字的**关系图不同构**（比如一个字里两横相接、另一个相离），那它们就不是同一个字的不同写法，而是两个字。

### 2. 辅助 OCR

笔段序列是介于图像与字符之间的中间符号层。**重叠率匹配**是这里最直接的手段：把候选字的笔段按一定缩放和平移投影上去，搜索使重叠面积最大的变换，以最大重叠率作为匹配分。

```
输入笔迹 ──▶ 抽象笔段 ──┐
                        ├──▶ 尺度搜索 ──▶ 最大重叠率 ──▶ 候选排序
字库笔段 ──▶ 抽象笔段 ──┘
```

关键在于"最大化重叠"这一步是有物理含义的：它同时容忍了书写时的位移、字号差异和比例失调，而这些恰恰是像素比对最容易失守的地方。在**手写体、碑刻、甲骨文**等训练数据稀缺的场景中，这个先验比端到端模型更可靠。

关系图可以放在重叠率之前当粗筛：先用结构签名（笔画数 + 部件数 + 两级的关系统计）把候选压到几十个，再做尺度搜索。签名对缩放完全不变，这一步几乎不花计算量，却能滤掉大部分形状相近而结构不同的字。

### 3. 拼字与造字

有了部件层和变换规则，就能用部件搭新字：

```
部件库（每个部件带自己的笔段结构、动作参数与关系图）
   │
   ├─ 选结构（相离 + 方位：左右 / 上下 / 内外；或让关系自己长出来）
   ├─ 定比例（按笔画数与视觉重量分配空间）
   ├─ 施加逐段变换（横缩、竖留、角迁移）
   ├─ 处理避让与穿插
   ├─ 复核第 1 级：部件关系图不变
   ├─ 复核第 2 级：各部件内部笔画关系图不变
   └─ 合成整字笔段 ──▶ 渲染或导出轮廓
```

第 6、7 条是这套流程能自动化的关键：拼字最容易出的错不是形状不对，而是关系被挤变了——两笔本该相离却被压到相接，或本想造成相接却拉开了。分成两级校验之后，报警位置直接指认错误来源：第 1 级报警说明部件间的间距或比例超限，第 2 级报警说明逐段变换的压缩量过大。有了这条硬约束，程序可以自己发现并回退，不必人眼逐字检查。

顺带一个结构性收获：既然结构类型只是"相离 + 方位"，那么**左右换上下**这种重排就不需要另写一套逻辑——换掉方位字段，比例与逐段变换的规则照旧，关系图仍应保持不变。这为同一字形的多种排布（异体、旧字形、竖排本）提供了统一的生成方式。

这既能为生僻字、方言字、新造字快速出字形，也能给字体设计师做草图——先看结构对不对，再谈笔形好不好看。

### 4. 少量设计生成整套字体

把笔画拆成"可复用的动作部件"：

| 参数族  | 控制什么              | 变体示例                                   |
| ---- | ----------------- | -------------------------------------- |
| 起笔习惯 | θ_in、ρ_in、l_in    | 楷（50°, 1.3） / 宋（30°, 1.1） / 黑（0°, 1.0） |
| 行笔习惯 | 笔段的力度型、是否有弧       | 楷（多为提、按提） / 宋（按→提） / 黑（全段平）            |
| 收笔习惯 | θ_out、ρ_out、l_out | ρ_out = 0（尖端）/ 1.2（方头）/ 1.0（平头）        |
| 衔接习惯 | ρ_neck、调锋位置       | 楷（0.7，钩前明显） / 宋（0.8） / 黑（1.0，无调锋）      |
| 折角习惯 | θ_turn、r、折处加粗量    | 宋（r≈0，加粗 1.4×） / 圆体（r>0.1）             |


一套"动作参数"描述一种书风。改一组参数，整库笔画同时改变，从而生成一整套风格一致的字体文件——设计师只需要设计几种典型笔画，而不是两万个字。

### 5. 字形统计与结构规律

抽象层让"结构"变成可以数的东西。例如统计左右结构字的宽度分配：

| 类型   | 判据               | 关注点              |
| ---- | ---------------- | ---------------- |
| 左小右大 | 左部件宽度 / 整字 < 0.4 | 左偏旁多为窄长竖类（氵、忄、亻） |
| 左右相当 | 0.4 ≤ 比值 ≤ 0.6   | 木、石、车 等可伸可缩的部件   |
| 左大右小 | 比值 > 0.6         | 右部件为口、攵等小件       |

同类指标还可以扩展到：上下结构的高度分配、包围结构的内部偏置、笔段方向直方图（横向占比、斜向占比）、笔段密度（单位面积段数，反映字形的疏密感）、重心位置、以及**关系类型分布**。关系分布要分两级统计，两级回答的问题不同：

- **笔画级**：相接 / 相交 / 相离各占多少，反映该字体的结构松紧（楷体偏相接，黑体偏相离）。
- **部件级**：⿰ 字里部件相离、相接、相交各占多少，反映该字体对"部件感"的处理——相离比例高，字看起来是"两块拼的"；相接、相交比例高，字看起来更整、更像一体。这一项可以直接检验"某款字体偏传统还是偏现代"这类判断。

这些统计可以直接回答"哪种结构在字体设计中更常见""某字体的疏密风格偏紧还是偏松"，也能反过来指导上面第 4 条的参数设定。

### 6. 笔顺示意图与动画

从字体里拆出的独立笔画，本身就是动画的关键帧：

```
1. 取每一笔的笔段序列（已按笔顺排序、带起止方向）
2. 沿笔段插值出书写路径（arc 段按凸度插值）
3. 用宽度参数画"笔尖"（起笔宽 → 收笔宽，模拟提按）
4. 生成 SVG 逐帧 / CSS stroke-dashoffset / Lottie
```

这套流程产出的不是简单的"描红"效果，而是带**起端加粗、中段收细、末端甩出**的书写动画——因为 w(s) 与端点参数本来就在抽象数据里。调锋还免费带来一样东西：**节奏**。颈缩处笔速自然放慢、笔压回升，钩前的那个停顿正是"起笔—行笔—收笔"之外最容易做假的地方，而在数据里它只是一个 t 值。适合小学语文的笔顺教学、生字卡、书写练习 App，也可以批量导出所有字的示意 GIF / 视频。

### 其他潜在用途

- 笔画层面的字体插值 / 变形
- 汉字结构统计与文字学研究
- 文字设计中的骨架提取与单线字（single-line font）生成
- 书法风格分析：把"起收笔习惯"量化成特征向量，用于断代或辨伪

## 现有相关工作

调研详见 [`调研报告-汉字笔画抽象.md`](./调研报告-汉字笔画抽象.md)。要点：

- **Make Me a Hanzi** — 9000+ 字的逐笔画 SVG 路径与**中线坐标（medians）**，可直接作为折线化的输入与校验基准。
- **Tegaki** — 从字体轮廓经 Delaunay 三角剖分求中线、再做宽度感知 RDP 简化的完整工程实现，并保留每点宽度，正好对应本项目的宽度参数。
- **《汉字的笔段网格字形描述及字形比对算法》** — 与本项目目标最接近的学术工作：有向笔段描述 + 最优匹配的字形比对。
- **KanjiVG / Hanzi Writer / stroke2vec** — 笔画数据、动画渲染、笔画类型编码，可分别用作参照与辅助特征。
- **KAGE / GlyphWiki、Wenlin CDL、汉字 METAFONT、HanGlyph** — 从有限笔形和部件包围盒**画出**轮廓，是本项目的逆方向。避让和部件比例可以对照，详见调研报告。

目前未见完全对等的开源项目：多数工作止步于"笔画路径"或"中线点序列"，尚未把笔画系统性地压缩为**带宽度动作的有向笔段序列**，并据此处理部件变换与结构统计。从参数生成轮廓的系统（KAGE、CDL）则没有从现成字体测量宽度曲线和笔画关系。

## 待测量验证

正文中的角度、宽度比，以及 δ、ε、0.02 em、30°、ρ_neck = 0.85、Δt = 0.06、弧残差 0.03 em，都是初值。下面各项先记在这里，等测量之后再决定是否改模型。

### 第一次测量

一款楷体、一款黑体，约 30 个字：横、竖、撇、捺、点、提、口、人、八、十、月、明、古、早、里。每笔输出中线折线和宽度曲线 w(s)。先回答三件事：

1. 楷体长横是否稳定地分成三段，中段是否为提按；黑体长横是否稳定地退化为一段、平。短横（如横折钩的第一段）是否保持一段。
2. 口、月、人、十、古的两笔间隙。δ 取平均笔宽的 0.5 倍时，相离与相接的分界落在分布的哪里。人与八的差别就在这个分界上。
3. 撇对一段弧的残差；0.03 em 会把撇切成几段。捺按三段（一波三折）拟合是否够，各段是直线还是弧。

宋体长横的段数和宽度动作尚未规定，有样品时与楷体、黑体一起量。

### 关系

- 测量时同时记下连续量：两笔最近距离、交点离最近端点的距离、交角。相离 / 相接 / 相交可以由这些量现算。阈值附近先看距离。
- 「变换下关系类型不变」先作为工作假设使用。月的单字与偏旁、楷体与黑体之间，要看类型是否翻转。
- 折叠目前取最强值（相交 > 相接 > 相离）。测量时同时记下一对部件之间三种关系各有多少条，再决定折叠要不要带上比例。一次粘连现在会把整对部件折成相交。
- 左右、上下可以用两块重心的方向表示。包围（⿵ ⿶ ⿷ ⿸ ⿹ ⿺）要另测「谁包含谁、开口朝哪」。结构类型能否只由折叠读出，等这批字的 IDS 与关系并排看过再定。
- 部件归属先以现有部件数据为准，关系图用来对照。两者不一致就记下来。原则 5 里「部件由关系图算出」与「部件数据是输入」的分工，测量后再定。
- 一笔穿过两个部件（如里、重的竖）有三种记法可试：整笔归一边、在某个 t 处切开、允许一笔对应两个部件。三种都先不写入模型。

### 中线与弧

- 每一笔若已是独立闭合轮廓，中线就逐笔计算。这一步要处理的是顿、斜切和尖端上的短枝，以及折、钩内部的分岔。Tegaki 的弦轴、剪枝、路口配对、按宽度做的 RDP 可以直接用；Zhang-Suen 只作对照。
- 凸度（矢高比）与 DXF 的 bulge 是同一个量。楷体撇往往越靠近尖端越弯。残差分布出来之前，期望结构表里撇的「1 段」只是一种待核的上界。

### 宽度与调锋

- 测量时先把 w(s) 的局部极小连同它的 t 记下来。钩前、捺末、反折之前若稳定出现颈缩，再决定调锋是否继续占一个身份。
- 身份和宽度动作量的是同一条 w(s)。先划 t 上的入笔 / 行笔 / 收笔，再在对应的段上判定宽度动作，避免两端的加粗和中段的提按抢同一次扫描。

### 比较、生成与数据格式

- 角度在数据里存连续值。比较时要不要收成 8 或 16 个方向槽，等距离分布出来再定。
- 避让还没有算子。KAGE 用随周围笔画改变顿笔和挑钩大小的局部规则。拼字，以及「少量参数生成整套字体」，都等测量、笔顺动画和字形比较之后再做。
- 重叠率匹配适合作为手写、碑刻的结构先验。中线要先按宽度膨胀成笔道，才能计算重叠面积。
- JSON 尚待写明：t 是中线弧长归一化；峰、谷的 t_p、t_v 是段内参数还是整笔参数；l_in 与 t 区间两套长度保留哪一套；坐标单位和 y 轴方向。示例「月」的 `relations` 引用了正文没有写出的第 3、4 笔，补例子时一起改。

### 生成侧可对照的系统

KAGE / GlyphWiki、Wenlin CDL、Hobby 与 Gu 的汉字 METAFONT、Yiu 的 HanGlyph，都是从参数画出轮廓。本项目从轮廓量回参数。部件比例和避让的做法见调研报告，先对照，不照抄。

## 术语

### 结构层

- **字** character——独立书写单位，有自身的包围盒与重心
- **部件** component——可独立成字、也可充当偏旁的结构块，由**一组笔画 + 它们之间的关系**构成
- **关系** relation——两笔之间的边，只有三个取值，是拓扑量
  - **相离**——无公共点，中线最近距离 d > δ（δ 取平均笔宽的 0.5 倍）
  - **相接**——有公共点，且交点是一笔的端点（端-端 / 端-身）
  - **相交**——有公共点，且交点不在任何一笔的端点
  - **关系图**——笔画为节点、关系为边的图，是部件的无形状表示
  - **不变量**——关系类型在部件变换（压缩、拼合、换字体）下不变，只有 d、t、交角这些几何量变；该性质在两个层级上都成立
- **部件关系**——两个部件之间的边，取值仍是同一套三个，由跨部件笔画对按"相交 > 相接 > 相离"折叠得到
  - **折叠** fold——由下级关系推出上级关系的运算，与"部件"一样是派生量，不单独存储
  - **结构类型**——相离关系的方位字段（左右 / 上下 / 内外）。包围的开口方向是否也能由此读出，见「待测量验证」。IDS 的 ⿰ ⿱ ⿵ 先按此理解
- **笔画** stroke——一笔连续的书写轨迹
  - **简单笔画**——不含转折（横、竖、撇、点、提）
  - **复合笔画**——含一个或多个转折（横折、横撇、横折钩、竖弯钩）
- **笔段** segment——抽象的最小几何单位
  - **直线** line——起终点确定，无弯曲
  - **单弧** arc——一段圆弧 / 二次贝塞尔
  - **凸度** bulge——弧的有符号矢高比，正负表示弯曲方向
  - **力度型** press——这一段的宽度怎么随弧长变，见下节
- **段数**——一笔的几何笔段数，有上界：长横最多 3、捺最多 3（一波三折）、横折钩 3。与身份数独立。具体字体可以少于上界
- **一波三折**——捺的段数上界：最复杂的捺分为三段。只表示段数，不作比喻
- **让**——部件之间为避让而做的空间调整

### 动作层

总纲：**动作 = 笔画弧长参数 t 上的一段标注，唯一维度是身份；区间长度为零时表示点动作。**
动作不是笔段的子类，是笔段的性质。身份说"这一段在笔画里扮演什么角色"；宽度怎么走由笔段的力度型回答，不在这里。

- **动作** action——挂在笔画 t 区间上的书写行为标注，属性为 `t` 区间、身份、以及身份对应的几何参数
- **身份** role——动作在笔画中的位置：三段（入笔、行笔、收笔）＋ 两点（转折、调锋）
  - **入笔**——笔画开端，参数 θ_in（起端方向偏角）、ρ_in（起端宽度比）、l_in（长度）
  - **行笔**——笔画主体，无额外参数，形态由笔段几何决定
  - **收笔**——笔画末端，参数 θ_out、ρ_out、l_out
  - **转折**——方向改变处，零长，参数 θ_turn（有向转角）、r（圆角半径）
  - **调锋**——两个动作之间的衔接，零长，参数 ρ_neck（颈缩深度 = w_min/w̄）、Δt（颈缩长度 ≤ 0.06）、δθ（方向偏移 < 30°）；判别式为 |θ_turn| < 30° 且 ρ_neck < 0.85，否则归转折或不记

### 笔段层：力度

- **力度** press——笔段沿弧长宽度 w(s) 的走向，一段一个力度型
  - **宽度动作**——平、提或按。一段至多两个。不另计力度段数
  - **平**——\|dw/ds\| < ε，宽度恒定（一个宽度动作）
  - **提**——dw/ds < −ε，变细（一个宽度动作）
  - **按**——dw/ds > ε，变粗（一个宽度动作）
  - **按提**——先增后减，一个峰；即按、提两个宽度动作。另带峰位 t_p、峰宽 w_p
  - **提按**——先减后增，一个谷；即提、按两个宽度动作。另带谷位 t_v、谷宽 w_v

### 已删除的词及理由

| 词                      | 处置                                                 |
| ---------------------- | -------------------------------------------------- |
| 顿入 / 尖入 / 平入           | 删除。只是 (θ_in, ρ_in) 平面上的三个区域，给数即可                   |
| 出锋 / 顿收 / 平收           | 删除。只是 ρ_out 的三个区间                                  |
| 悬针 / 垂露                | 删除。是"尖收 / 重收"用在竖上的别名                               |
| 藏锋 / 露锋                | 删除。由 ρ_in 与 θ_in 决定，无独立数值轴                         |
| 驻 / 挫 / 涩行             | 删除。仅靠手感区分，印刷体中无稳定可测形态                              |
| 调锋 / 换锋 / 翻笔 / 绞转 / 暗过 | 换锋、翻笔、绞转、暗过删除（软笔的锋面操作）；**调锋恢复**，理由见下               |
| 中锋 / 侧锋                | 删除。印刷字体中差异极小                                       |
| 一波三折                   | 收回。只作捺的段数上界：最复杂的捺分为三段。不再当作比喻                     |
| 独体字                    | 删除。只有一个部件的字就是一个部件                                  |
| 力度段 / 力度段数             | 删除。一段里最多两个宽度动作（按提、提按）；更细的变化用更多几何段表达，段数另有上界      |
| 顿                      | 不单列。是力度型"按提"的峰，或端点加粗（记在 ρ_in / ρ_out）；只是曲线上的一个事件，不是类型 |
| 匀                      | 改名为**平**。原为躲开"平截 / 平收"，那些词删除后"平"空了出来，且它同时指宽度平与笔道平 |
| 方折 / 圆转 / 顺折 / 反折（搭锋）  | 暂不收录为术语。只是 (r, |θ_turn|) 切出的区域，正文里作说明性用词，不进词表、不进数据 |
| 尖收 / 平截 / 重收           | 暂不收录为术语。只是 ρ_out 的三个区间，同上                          |

原则：**能算的不命名，不能算的不保留。** 任何新增术语都必须先给出参数与阈值，否则不予收录。

**一处回退：调锋。** 早先版本把它删掉，理由是"视觉结果已并入 (θ_turn, r)"。这个判断对转折成立，对别处不成立——钩前、捺末、反折之前的那个细腰并不伴随方向改变，删掉它之后这些位置在数据里就整个消失了。而生成与动画恰恰需要知道"动作在哪换"。所以它按规矩回来了：因为留下可测痕迹（w 的局部极小），所以给三个参数与两条阈值；因为它描述的是序列位置而非形状，所以进身份，不进标签。
